the data should be viewable to the user on the left side of the screen as a navigable table, where each dict in the list nba_data represents a row, and the keys of each dict are the column headers of the table. on the top right side of the screen the user is asked to query some subset or summary of the data in the table. for example, they may be asked to return all the oponents against which Lebron James scored more than 20 points. Or they may be asked to return the average number of offensive rebounds for all players on the lakers (LAL). these questions should be generated by querying a free LLM, using the structure of the dataset as context. the LLM should return a question and the correct SQL query that would answer that question. Below the question on the right side of the screen the user is able to enter SQL commands. Upon submitting a command, the results of the query are shown to the user in the bottom right part of the screen. the user may submit as many queries as they want, and each time the results are replaced by those of the most recently submitted query. if the user's query results are identical to those that would result from the correct SQL query, then a green checkmark appears over the right side of the screen, there is a brief pause, the user query and associated results disappear, and a new question is presented.

if the question does not specify certain columns to be returned, then that should not be part of the criteria for determining a correct response

next to where it says Run SQL and Clear have a toggle for Question Mode. This is on by default (existing behavior). If the user toggles it off, everything associated with the question is hidden, including the option for a new question and any text that would show for correct or incorrect answers.

when entering the page for the first time, the page should load with question mode turned off
